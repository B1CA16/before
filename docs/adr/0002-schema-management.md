# ADR 0002: Database schema managed by Supabase CLI and hand-written SQL

- Status: accepted
- Date: 2026-07-20

## Context

We use Supabase (Postgres + PostGIS). ADR-0001 commits us to reproducible, versioned schema
changes, and the data is geospatial. Options weighed for managing schema: the Supabase CLI with
hand-written SQL migrations; SQLAlchemy + Alembic (Python ORM with autogenerated migrations); or a
lightweight SQL runner such as dbmate.

## Decision

Manage the schema as hand-written SQL migration files applied via the Supabase CLI, stored in the
repo. Migrations are pushed to the hosted free-tier database. The local Docker stack is optional
and used only later if we want offline development or migration diffing.

## Consequences

- PostGIS (geometry/geography columns, GIST indexes, extensions) is first-class in raw SQL and
  stays transparent, which suits both the domain and the learning goal.
- We write DDL by hand rather than generating it: more typing, but nothing hidden.
- Typed client generation for the API and frontend is available from the CLI later.
- We avoid an ORM's abstraction and Alembic's weak PostGIS autogenerate. If CLI or Docker friction
  grows, a lightweight SQL runner (dbmate) is the fallback. We deliberately did not choose Alembic
  for this reason, despite it being a strong general-purpose tool.
